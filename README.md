# CommonGround — Qloo Agentic Hackathon

**Public preview:** https://meowrona.github.io/CommonGround/

**Public source:** https://github.com/MeowRona/CommonGround

CommonGround helps two people with different tastes find **one movie that each person reaches for a different reason**.

The core interaction is intentionally narrow:

1. each person provides 1–3 films or artists;
2. Qloo resolves those inputs to entities;
3. Qloo independently discovers movie candidates for A and B;
4. CommonGround unions those candidates and asks Qloo to evaluate the **same movie pool** for both people;
5. candidates missing an evaluation on either side stay **unknown** instead of becoming zero;
6. CommonGround minimizes the worse rank first, then the sum of both ranks;
7. it proposes one bridge movie;
8. both people react: **Want to try / Already know / Not for me**;
9. a veto or already-known result is excluded and triggers one wider second round;
10. after two rounds, the agent stops rather than forcing a compromise.

## Why Qloo matters

Without Qloo, the intended product loses its core capability: cross-domain cultural relationships from inputs such as films + artists to a movie candidate pool, plus per-result explainability metadata.

The application layer does **not** claim to predict whether a person will like something. It uses Qloo's result ordering as query-context evidence, then applies a transparent two-person decision policy.

## Public preview vs live mode

The GitHub Pages preview is deliberately limited to fixed test scenarios generated by the Python decision engine. It does **not** accept arbitrary text and does **not** claim to be live Qloo output.

This avoids the old failure mode where random text could receive a meaningless synthetic percentage.

- `COMMON_GROUND_MODE=fixture` — local/public development fixtures.
- `COMMON_GROUND_MODE=live` — real Qloo `/search` + `/v2/insights` flow.

The live client already implements:

- entity resolution via `/search`;
- movie discovery via `/v2/insights`;
- `feature.explainability=true`;
- candidate exclusions via `filter.exclude.entities`;
- same-pool evaluation via `filter.results.entities`;
- defensive parsing and fail-closed behavior when response structure is unexpected.

The remaining live gate is a real hackathon API key and one schema smoke test against the competition environment.

```

```

## Decision policy

For every movie that has measurements on both sides:

1. minimize `max(rank_A, rank_B)`;
2. break ties with `rank_A + rank_B`.

Example: `A=#1 / B=#9` loses to `A=#6 / B=#6`, even though average rank prefers the first candidate. This is a simple least-misery-style protection rule, not a novel preference model.

## Current validation

The test suite covers:

- random/unrecognized text failing instead of generating fake recommendations;
- a candidate found only in A's discovery still being evaluated for B;
- same-pool evaluation request parameters;
- missing evaluation staying unknown;
- worse-rank protection (`1/9` vs `6/6`);
- second-round widening and veto persistence;
- hard two-round limit;
- candidate-specific evidence;
- live search/insight response parsing fixtures;
- secret-safe HTTP errors.
